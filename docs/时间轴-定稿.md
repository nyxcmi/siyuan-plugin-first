# 模块定稿：时间轴（timeline）

> 定于 2026-11-18，**2026-11-18 晚修订**：数据模型从「一篇文档 = 一天」改为「一个日期标题 = 一条记录」。
> 这一页是施工依据。不在这一页上的功能一律不做。

---

## 一、目标

一个侧栏面板，两个 tab，共用同一份数据：

| tab | 用途 | 读法 |
|---|---|---|
| **时间轴** | 定位："我记得那阵子写过什么" | 一条一屏，紧凑，可跳转 |
| **连续阅读** | 沉浸："把这一段时间重读一遍" | 条目连排，像一本书 |

---

## 二、数据模型（修订核心）

**你的日记不是"一天一篇文档"，而是"合订本里有很多日期小节"。**

```
文档（5-6月 / 7-8月 / 2026-11-07 周六 …）
  └── 标题块（H1–H5）
        └── 条目 = 日期 + 该标题到下一个标题之间的内容
```

```ts
interface DiaryEntry {
  blockId: string       // 标题块的 id
  docId: string         // 所属文档
  docTitle: string      // 所属文档标题，如 "5-6月"
  date: Date            // 解析出的日期
  rawTitle: string      // 原标题原文，如 "20260504 Mon-周记模板搭建"
  plain: string         // 该条目正文的纯文本（前 300 字，给摘要用）
  words: number
  mood?: { score: number; emoji: string }
  imageCount: number
}
```

**同一篇文档里可以解析出多条记录。** 一篇 `5-6月` 里有十几天的记录，时间轴上就是十几个节点。

---

## 三、日期格式（唯一标准）

**标准格式：`YYYY-MM-DD`**，例如 `2026-11-18`。

- **标题里不写星期**，星期由程序按日期计算，界面显示 `2026-11-18 周三`
- 解析只有一个正则，不存在"猜格式"
- 可排序（字符串序 = 时间序）、可解析、和文件名一致

**历史格式（6 种）不做兼容。** 它们不进入读路径——读到不匹配就是不显示。

旧数据的处理走**单独的迁移工具**（后续实现）：

- 扫描文档标题与内部标题 → 识别旧格式 → 改写成标准格式 → 报告改动了哪些
- 有特殊格式的，可以**单独指定**它的解析规则（后续功能），不进主流程

**实测（2026-11-18）**：dev 库里 24 篇文档、旧格式共 74 条；其中符合标准格式的单日文档 5 篇。**规范化后时间轴才会有完整数据。**

---

## 三·补、条目正文如何取

条目只存元数据（日期、标题、所属文档、块 ID）。**正文按需加载**，不在列表阶段拉全文：

- 时间轴 tab：只显示摘要 → 取前 N 字时再请求
- 连续阅读 tab：进入某段区间时按需取全文

这样即使文档上百篇，打开面板也不会卡。

## 四、字段注册表（架构核心）

```ts
const FIELD_REGISTRY = {
  date:     { label: "日期",   render: (e) => 日期标题 },
  mood:     { label: "心情",   render: (e) => e.mood ? `${e.mood.emoji} ${e.mood.score}` : "" },
  excerpt:  { label: "摘要",   render: (e, cfg) => 截取(e.plain, cfg.excerptLength) },
  title:    { label: "原标题", render: (e) => e.rawTitle },
  images:   { label: "图片数", render: (e) => e.imageCount ? `${e.imageCount} 张` : "" },
  words:    { label: "字数",   render: (e) => `${e.words} 字` },
  fulltext: { label: "全文",   render: (e) => 渲染条目正文 },
}
```

加字段 = 注册表加一行 + 配置界面自动多一个选项。渲染代码不改。

## 五、默认配置（两套独立）

**两个 tab 的粒度不同，这是设计要点：**

| | 时间轴 tab | 连续阅读 tab |
|---|---|---|
| **粒度** | **按天合并**（同一天多条并成一格） | **按条展开**（同一天两条就两段） |
| 字段 | `date, mood, excerpt` | `date, title, fulltext` |
| 摘要长度 | 50 字 | — |
| 排序 | 新 → 旧 | 旧 → 新 |
| 打开位置 | 顶部 | 滚到最新 |
| 分页 | 滚动 | 滚动 / 加载更早 / 按周翻 |

> 为什么这样分：时间轴的用途是"定位"，一天一个位置最好扫；阅读的用途是"沉浸"，同一天写了两段就该连着读。**同一份数据，两种粒度。**

---

## 六、可配置项（只有 4 项）

1. 显示哪些字段（多选 + 排序）
2. 摘要长度
3. 分页方式
4. 数据源笔记本（默认 `1.daily note`）

入口两处，改同一份配置：**面板顶部齿轮** + **插件设置页**。

存储：`plugin.saveData("timeline-config", {...})`

---

## 七、交互

| 操作 | 行为 |
|---|---|
| 点条目 | `openTab` 打开所属文档，并滚动/定位到该标题块 |
| 切 tab | 不重新查库，只换渲染 |
| 悬停 | 显示完整日期、所属文档、字数 |

---

## 八、明确不做

- ❌ 不修改任何文档（**整个模块只读**）
- ❌ 不渲染图片缩略图（只显示张数）
- ❌ 不做搜索
- ❌ 不做统计图表
- ❌ 不做自定义模板 / CSS / 条件规则
- ❌ 不做"手动指定哪些文档参与"（靠日期解析自动排除）

---

## 九、风险

| 风险 | 应对 |
|---|---|
| 日期格式以后又变 | 解析器写成可扩展的格式数组，新增格式加一条规则 |
| 条目正文太大 | 摘要只取前 300 字；全文渲染分批，每 10 条一批 |
| 心情读取失败 | 该项留空，不阻塞渲染 |
| 标题层级混乱 | 只把"含日期"的标题当条目，其余忽略 |

---

## 十、验收标准

1. 打开面板 → 时间轴能看到历史记录（不止 6 条，应该几十条）
2. `5-6月` 这一篇文档能拆出十几条，日期正确、顺序正确
3. `0518` 这种缺年份的能正确补成 `2026-05-18`
4. 连续阅读：能把 9 月整月连起来读
5. 配置里取消"摘要" → 立刻消失，不用重开面板
6. 点条目 → 跳到所属文档并定位到那段
7. `人物列传`、`陈子豪` 等**不出现**在时间轴
